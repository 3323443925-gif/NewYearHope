## 1. 产品愿景与核心价值

### 1.1 背景与愿景
在新年到来之前，人们心中往往藏着许多“未能说出口的话”，也怀抱着对新一年的希望与愿望。本项目旨在打造一座**基于“真、善、美”的冬夜星光浮岛网站**：
- **始于岁末迎新**：在 1 月到来前，承接人们对旧岁的告别与对新年的期许；
- **止于长久陪伴**：过了 1 月后依然永久开放，成为全球任何人在孤独、寂寞或需要微光时，随时可以推门进入、留下痕迹并获得陌生人善意慰藉的心灵角落。

### 1.2 核心价值观落地
- **真（Authenticity）**：零门槛免登录、支持匿名或自由署名，允许坦诚倾诉心声与愿望，并赋予用户随时收回自己留言的掌控感。
- **善（Kindness）**：鼓励陌生人之间互相问好、轻柔安慰与点亮祝福；通过智能内容审核、隐私脱敏与防恶意机制守护社区纯净。
- **美（Aesthetics）**：以深蓝星空、暖金星光浮岛、漂浮孔明灯与每日 0 点燃尽升空的烟花，营造静谧、治愈、克制的沉浸式视觉与声景体验。
- **快（Performance）**：以极速访问和流畅运行为底线，兼顾移动端与桌面端，让每一份情绪都能在 2 秒内被温柔接住。

### 1.3 品牌命名与 Slogan（已确认）
- **中文名**：星屿祈光
- **英文名**：Starlight Isle
- **中文 Slogan**：给未说出口的话，和新年愿望的一座光屿
- **英文 Slogan**：*A quiet island for unspoken words & new year wishes.*
- **仓库/项目代号**：`NewYearHope`（延续初心，致敬新年与希望）

## 2. 目标用户与使用场景

- **受众范围**：面向全球用户，原生支持 **简体中文 / English** 双语一键切换。
- **终端覆盖**：**移动端与桌面端双端兼顾**（包含手机主流浏览器、微信/社媒内置浏览器、PC/Mac 浏览器）。
- **典型场景**：
  1. **岁末倾诉者**：在 12 月的深夜打开网站，无需注册，写下今年没能对某人说出口的话，配上一张晚霞照片，放飞成一盏星灯。
  2. **新年许愿者**：挑选一枚温暖的心情贴纸，写下 2027 年愿望，静看岛边礼花筒的引线慢慢燃烧，等待本地 0 点烟花升空。
  3. **寻找慰藉与传递善意的人**：在感到孤单的夜晚回到小岛，点开几盏飘过的陌生人孔明灯，留下一句真诚的安慰或点亮“抱抱你”，同时也看看自己曾放飞的那盏灯是否收到了回信。

## 4. 视觉设计、3D 场景与时间仪式感

### 4.1 视觉语言与配色
- **主氛围**：深邃静谧的冬夜星空（冷蓝）× 圣诞树/孔明灯/引线火花（暖金与暖橘），形成治愈的冷暖对比。
- **参考色板**：
  - 夜空渐变：`#050B1E`（天顶）→ `#0E1F45`（地平星云）
  - 浮岛积雪：`#D8E6FF`（受光微蓝白）与 `#5D76A8`（雪影）
  - 暖金光晕：`#FFD984`（树顶之星、灯串辉光）
  - 孔明灯暖橘：`#FF9E57`（新年愿望）/ 月白淡金 `#EAEFFF`（未说出口的话）
  - 玻璃拟态 UI：`rgba(12, 22, 48, 0.65)` + `backdrop-filter: blur(12px)` + 细微暖金描边，确保阅读清晰且不抢戏。

### 4.2 核心 3D 场景元素
1. **中央微缩雪夜浮岛**：
   - 悬浮于星空中的积雪岛屿，底部带淡淡冰棱与浮空投影；
   - 中心为一棵带暖色彩灯与顶部星光的立体圣诞树，周围错落点缀数棵小型雪松；
   - 支持鼠标拖拽/单指滑动 360° 轻柔旋转视角、双指/滚轮有限范围缩放；无操作时保持极慢速度自动旋转（类似参考图 `autoRotateSpeed` 节奏），同时夜空飘落细碎微雪与闪烁繁星。
2. **微缩星光礼花筒 & 本地 24 小时燃烧引线**：
   - 立于浮岛边缘雪地的暖木/暗金质感微缩礼花筒，避免与雪夜画风割裂；
   - 一根细长发光引线盘绕在雪地上，末端持续冒出柔和的微暖火星；
   - **进度规则**：严格对应**访客设备本地时间** `00:00:00 ~ 23:59:59`（例如 12:00 燃至一半，23:55 火星已紧贴筒口）；
   - **交互提示**：点击礼花筒弹出精致微气泡，显示“距离今天 0 点烟花还有 `HH:MM:SS`（本地时间）”；
   - **每日 0 点绽放**：本地时钟抵达 `00:00:00` 瞬间，引线燃尽，礼花冲上夜空绽放一场约 15~30 秒的暖金、冰蓝、淡粉星光烟花，随后新的一天引线重新点亮。
   - **体验兜底**：若用户当天打开时不是 0 点，可在倒计时气泡内提供“预览一朵小小星火 / 重温昨夜烟花”轻触发按钮（不影响真实 0 点集体仪式感，P1 可增强）。
3. **留言的视觉化身（孔明灯 & 星愿光球）**：
   - 用户的每一条留言**直接化为一盏环绕浮岛缓慢上升/盘旋的光体**，而非生硬文字气泡：
     - **新年愿望 / 希望**：暖橘色发光孔明灯；
     - **未能说出口的话 / 怀念**：月白/淡金色发光星愿球；
     - **给陌生人的问好**：柔粉色/琥珀色星尘灯；
   - **“我的灯”专属标识**：本设备发出的灯带有一圈柔和的星环微光，便于用户一眼认出。

### 4.3 临近 1 月 1 日的渐进视觉演进（按访客本地日期自动切换，P1 完整落地）

## 5. 核心功能需求详解

### 5.1 页面布局与信息架构（极简沉浸式）
全屏以 3D 夜空浮岛为核心画布，UI 控件克制悬浮于边缘，不遮挡视觉主体：
- **顶部左区**：网站名微标 + 当前日期/阶段小语（例如“距 2027 还有 35 天”）。
- **顶部右区**：
  - `中 / EN` 双语切换按钮；
  - `我的灯` 入口（含新回复小红点提示）；
  - 声音开关（P1）；
  - `关于与开源` 轻量图标（展示“真善美”初心、免责说明与 GitHub 链接）。
- **底部居中操作区**：
  - 主按钮：**「放飞一盏灯 / Light a Lantern」**（暖金微光胶囊按钮）；
  - 辅助轻按钮：**「换一批夜空 / Refresh Sky」** 与 **「随机拆一盏灯 / Catch a Light」**。

### 5.2 F1：浏览与探索夜空留言
- **同屏显示上限与轮换策略**：
  - 为确保画面通透与高性能，同屏最多渲染 **桌面端 50 盏 / 移动端 30 盏** 漂浮灯盏；
  - 选灯优先级：**本设备“我的灯”（优先可见）** + **近期活跃/最新留言** + **历史随机缘分留言**；
  - 用户点击“换一批夜空”可平滑淡出旧灯、升起新一批星灯。
- **悬停与点击交互**：
  - 桌面端鼠标悬停在灯盏上（移动端轻触第一下或直接点击）：灯盏略微变亮放大，浮现轻提示（昵称 + 心情图标 + 正文前 18 字预览）；
  - 点击灯盏：镜头柔和微调，屏幕中央展开半透明玻璃态**「夜空信笺弹窗」**，展示完整内容。

### 5.3 F2：免登录放飞留言（核心写路径）
用户点击「放飞一盏灯」，弹出简洁温柔的书写卡片：

| 字段 | 是否必填 | 规则与说明 |
| :--- | :--- | :--- |
| **留言类型** | 必填（默认第 1 项） | `新年愿望`（孔明灯）/ `未说出口的话`（星愿球）/ `向世界问好`（星尘灯） |
| **心情标签** | 必填（单选） | 预设 6~8 个温柔心情（如：期待、想念、释怀、孤单、感恩、加油），配统一风格的极简图标 |
| **留言正文** | 必填 | 1 ~ 500 字符（支持换行，过滤连续过多空行） |
| **署名昵称** | 选填 | 0 ~ 20 字符；留空则按当前语言展示 `匿名旅人` / `Anonymous Traveler` |
| **治愈贴纸** | 选填（单选） | 内置 8~12 枚统一美学的矢量/手绘风贴纸（如热可可、星星、雪人、纸飞机、向日葵、小猫等），零网络负担 |
| **上传图片** | 选填（最多 1 张） | 支持 JPG/PNG/WebP/HEIC（转码）；**前端上传前自动压缩至长边 ≤ 1280px、大小 ≤ 300KB 的 WebP，并剥离 EXIF 隐私信息** |
| **互动权限开关** | 必填（默认开启） | 默认勾选：`允许陌生人留言安慰与问好`；关闭后则显示为`仅接收点亮祝福（关闭文字回复）` |

- **放飞反馈仪式**：
  - 提交通过实时安全校验后，书写弹窗收起并化为一盏新灯从雪地浮岛缓缓升空，画面提示“你的光已升入夜空 ✨”，同时自动记录至本机“我的灯”。

### 5.4 F3：互相问好、自由回复与点亮祝福
点开任意一盏星灯后的信笺弹窗包含：
1. **信笺主体**：分类标识、贴纸、心情标签、正文、可选附图（点击可查看大图）、昵称、相对发布时间（如“2 小时前”）。
2. **轻祝福栏（始终可用，即便发帖人关闭文字回复）**：
   - 提供 3 个温暖快捷祝福按钮及累计次数：
     - `祝你如愿 ✨` / `May it come true`
     - `抱抱你 🤍` / `Sending a hug`
     - `新年好 🎇` / `Happy New Year`
   - 规则：同一设备对同一盏灯每种祝福仅可点亮 1 次，点击时触发细腻的星光粒子反馈。
3. **温暖回信区（仅当发帖人开启“允许回复”时展示）**：
   - **默认对所有人公开可见**，按时间正序展示所有回复，支持“加载更多”；
   - 若发帖人关闭回复，此处展示温柔文案：“这盏灯的主人选择静静珍藏心事，你可以为他点亮一份祝福 ✨”；
   - **回复输入表单**：免登录，选填昵称（0~20 字）+ 回复内容（1~300 字），提交经安全校验后即时上屏。
4. **顶部辅助操作**：右上角提供低干扰的 `举报 / Report` 入口；若是“我的灯”，提供 `收回这盏灯 / Retract` 入口。

### 5.5 F4：本机记住“我的灯”与自主撤回
- **无感本机身份**：用户首次放飞留言时，前端在 `localStorage` 生成并持久化一份高熵随机 `owner_secret`（服务端仅存储其 SHA-256 哈希值作为该灯的删除凭证），同时缓存本地放飞的 `lantern_id` 列表及最近查看回复数。
- **“我的灯”面板**：
  - 点击右上角「我的灯」，侧边/底部抽屉列出本设备放飞过的所有灯盏；
  - 若某盏灯有了新的陌生人回复或祝福，显示柔和暖金圆点提示；
  - 点击列表项可直接打开信笺或在夜空中定位高亮该灯。
- **自主撤回 / 删除**：
  - 在“我的灯”详情中点击「收回这盏灯」，弹出温柔二次确认（“收回后，这盏灯与上面的文字将从夜空轻轻熄灭且无法恢复，确认吗？”）；
  - 携带本机 `owner_secret` 请求删除接口，服务端核验哈希后执行软删除（立即在全站不可见并清理关联存储图片）。
  - *提示文案*：在“我的灯”抽屉底部柔和提示“记录保存在当前浏览器中，清除浏览器数据后将无法找回管理权限”。

### 5.6 F5：中英双语国际化（i18n）
- **自动识别**：首次访问读取 `navigator.language`（中文环境默认简体中文，其余默认英文），并将用户手动切换的偏好存入 `localStorage`。
- **全量界面翻译**：所有按钮、导航、提示、心情、分类、时间格式化（如 `3h ago` / `3 小时前`）、倒计时、错误提示均严格维护在 `locales/zh.json` 与 `locales/en.json` 中，便于后续开源社区新增语种。
- **UGC 原则**：用户书写的留言与回复原文保留原语种展示，不强行机翻破坏语感。

## 6. 内容安全、合规与“真善美”守护机制（方案 A）

由于采用 **免登录 + 自由上传照片 + 自由回复**，必须建立严密而克制的安全护栏：

1. **智能过滤（先发后审的核心防线）**：
   - **文本实时检测**：发布留言和回复前，先过内置中英文敏感词/广告特征过滤器 + 第三方文本内容安全/AI 审核接口（拦截色情、暴力、仇恨辱骂、外链引流、刷屏垃圾信息）；不通过时返回温和提示（“为了让这片夜空保持温柔，请调整一下措辞再试哦”），不直接暴露敏感词规则。
   - **暖心守护彩蛋（善意兜底）**：若文本检测识别到明显的自伤或极度危机倾向，不冷冰冰报错，而是温柔弹出**全球/国内免费心理援助热线卡片**，传递真正的善意。
   - **图片实时审核**：本地上传图片在入库公开前，必须通过第三方图片安全审核 API（鉴黄/暴恐/涉政/二维码引流检测）；审核未通过立即拦截并删除临时文件。
   - **隐私脱敏**：强制在上传链路去除照片 EXIF 元数据（防止泄露用户的拍摄经纬度 GPS 信息）。
2. **防刷与限流**：
   - 基于 IP + 匿名设备标识做速率限制（参考：每分钟最多放飞 1 盏灯、最多发 3 条回复；每小时最多放飞 5 盏灯）；
   - 异常高频或可疑请求时触发无感人机验证（如 Cloudflare Turnstile），正常用户全程无感。
3. **社区共治与自动折叠**：
   - 每条留言和回复均支持用户举报（原因：广告引流 / 不友善内容 / 不当图片 / 其他）；
   - **自动隐藏阈值**：同一内容被 ≥ 3 个独立设备举报时，自动设为“待复核隐藏”状态，第一时间止损，进入管理员待审队列。
4. **极简管理后台（Admin Panel）**：
   - 独立隐藏路由 + 管理员密码/Token 登录保护；
   - 支持按“被举报待处理 / 最新留言 / 含图片留言 / 最新回复”筛选浏览；
   - 支持一键**删除（熄灭灯盏）/ 忽略举报恢复展示 / 封禁恶意 IP**。

## 7. 非功能性需求：性能、兼容性与可访问性

### 7.1 极速访问与性能指标（核心红线）
| 维度 | 目标指标 | 实现策略 |
| :--- | :--- | :--- |
| **首屏渲染** | FCP `< 1.2s`，LCP `< 2.0s`（常规宽带/4G） | 静态资源全球 CDN 分发；HTML 首屏即刻呈现深蓝渐变星空背景与顶部文案，零白屏等待 |
| **渐进加载** | 3D 场景异步加载不阻塞 UI | 先渲染极简 UI 与静态星空底图，异步拉取 Three.js 场景与首批 30~50 条灯盏元数据后柔和淡入 |
| **3D 轻量化** | 3D 资产总下载量 `< 500KB`（gzip 后） | **优先使用程序化低多边形（Low-Poly）几何体**构建雪岛、圣诞树与孔明灯，避免动辄数 MB 的外部 `.glb` 大模型；雪花、星星、孔明灯大量采用 `InstancedMesh` 合批渲染减少 Draw Calls |
| **帧率与功耗** | 桌面端稳定 60fps，中低端手机稳定 ≥ 30fps | 限制像素比 `Math.min(window.devicePixelRatio, 2)`；Bloom 辉光按设备性能自适应降级；监听 `document.visibilitychange`，切后台自动暂停渲染循环 |
| **弱机兜底** | 不支持 WebGL 或低帧率自动降级 | 自动回退至轻量 **Canvas 2D / CSS 星夜场景**，保留完整留言、孔明灯漂浮与烟花体验，绝不崩溃或卡死 |
| **图片加载** | 列表零大图流量 | 仅当用户点开某盏信笺时才懒加载其附图，且全部为压缩后的 WebP + CDN 缓存 |

### 7.2 双端适配与无障碍
- **移动端适配**：竖屏下自动拉远相机视角保证浮岛完整居中；适配 iOS/Android 安全区（`env(safe-area-inset-*)`）；弹窗输入框兼容软键盘弹出不被遮挡；兼容微信内置浏览器（避免依赖易被拦截的特殊 API）。
- **减弱动态效果**：尊重系统 `prefers-reduced-motion` 设置，并在设置里允许用户手动切换“极简省电模式”。

## 8. 推荐技术架构与数据模型（面向 5 天 AI 辅助开发 & GitHub 开源）

### 8.1 推荐技术栈（兼顾开发效率、全球速度与低成本）
- **前端框架**：`React` + `TypeScript` + `Vite`（或 `Next.js` App Router），`Tailwind CSS` 负责玻璃拟态 UI 与双端响应。
- **3D 与动画**：`Three.js`（搭配 `@react-three/fiber` + `@react-three/drei` 或原生 Three.js 轻量封装以进一步压低包体积）+ 自定义轻量化烟花粒子系统。
- **后端与存储（任选其一快速落地）**：
  - **全球极速方案（推荐）**：`Cloudflare Pages + Workers`（或 `Vercel`）+ `Supabase`（Postgres 数据库 + RLS）+ `Cloudflare R2`（图片对象存储 + 全球 CDN，无出站流量费）。
  - *国内访问提示*：若初期大量用户来自中国大陆，务必绑定已备案域名或选用国内友好的加速线路/对象存储，确保微信内点开秒开。
- **内容安全 API**：OpenAI Moderation API / Perspective API（英文友好）+ 国内云厂商内容安全（阿里云/腾讯云文本+图片审核，中文准确率高），封装成可插拔的 `ModerationProvider` 接口，方便开源社区自由替换。

### 8.2 核心数据表设计（Schema 概览）
1. **`lanterns`（星灯/留言主表）**
   - `id` (UUID, PK)
   - `type` (ENUM: `wish` | `unspoken` | `greeting`)
   - `mood` (VARCHAR: 心情代码)
   - `content` (TEXT, 1~500 字)
   - `nickname` (VARCHAR, 可空)
   - `sticker_id` (VARCHAR, 可空)
   - `image_url` (TEXT, 可空)
   - `allow_replies` (BOOLEAN, default `true`)
   - `owner_secret_hash` (VARCHAR, SHA-256 哈希，用于本机自主撤回校验)
   - `bless_wish_count` / `bless_hug_count` / `bless_newyear_count` (INT, default `0`)
   - `reply_count` (INT, default `0`)
   - `status` (ENUM: `active` | `hidden_by_report` | `deleted_by_owner` | `deleted_by_admin`)
   - `report_count` (INT, default `0`)
   - `locale` (VARCHAR: `zh` | `en`)
   - `ip_hash` (VARCHAR, 脱敏哈希用于限流与封禁)
   - `created_at` (TIMESTAMPTZ)
2. **`replies`（回复表）**
   - `id` (UUID, PK), `lantern_id` (FK -> `lanterns.id`), `content` (TEXT, 1~300 字), `nickname` (VARCHAR), `status` (`active` | `hidden_by_report` | `deleted_by_admin`), `report_count` (INT), `ip_hash` (VARCHAR), `created_at` (TIMESTAMPTZ)
3. **`reports`（举报表）**
   - `id` (UUID, PK), `target_type` (`lantern` | `reply`), `target_id` (UUID), `reason` (VARCHAR), `reporter_hash` (VARCHAR), `created_at` (TIMESTAMPTZ)

### 8.3 GitHub 开源准备规范
- 所有 API Key、管理后台密码、审核密钥均通过 `.env.example` 配置，严禁硬编码；
- 提供 `README.md`（中英双语）、`CONTRIBUTING.md`、开源协议（建议 **MIT License**）；
- 审核模块与存储模块做抽象封装，支持开发者本地 `npm run dev` 一键 Mock 启动体验，降低社区贡献门槛。
